## 本机可选骨干和取舍

本机 TorchVision 0.25.0 提供 ResNet18/34/50/101/152、ResNeXt、Wide ResNet 等；新卷积头入口已核验 ResNet18/34/50、ResNeXt50、RegNetY-400/800MF、EfficientNet-B0/V2-S、ConvNeXt Tiny、MobileNetV3 Large 的 448 输入 14×14 特征，见[版本说明](../versions/yolov1.md)。`resnet30` 不是 TorchVision 模型名。官方接口 `get_model`/`get_model_weights` 可加载明确命名的预训练权重；权重不在缓存时会下载。[TorchVision 模型与权重文档](https://docs.pytorch.org/vision/stable/models.html)、[ConvNeXt Tiny 权重](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.convnext_tiny.html)。

用户补充的三个候选中，ResNeXt50 与 ResNet50 计算量接近，而 RegNetY-800MF 可提供轻量级对照；EfficientNetV2-S 的计算量较大，当前准确率目标下暂不优先完整训练。TorchVision 公布的 224/384 分类输入基准分别约为 ResNeXt50 `4.23`、RegNetY-800MF `0.83`、EfficientNetV2-S `8.37` GFLOPs；这些数字**不是**本项目 448 检测模型的实际耗时，选型仍需看实测。来源：[ResNeXt50](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnext50_32x4d.html)、[RegNetY-800MF](https://docs.pytorch.org/vision/0.15/models/generated/torchvision.models.regnet_y_800mf.html)、[EfficientNetV2-S](https://docs.pytorch.org/vision/0.17/models/generated/torchvision.models.efficientnet_v2_s.html)。

当前模型的首个全连接层约 2.06 亿参数，仅 VOC2007 train 的 2,501 张图参与训练。更大 backbone 本身未必改善这一瓶颈。因此按顺序试验：

1. **检测头对照：** [ResNet50 卷积头 recipe](../../configs/yolov1/voc2007_resnet50_convhead.yaml)沿用相同 ResNet50 ImageNet 文件、train/val、随机种子、冻结 5 轮、Adam 学习率、batch、增强、YOLOv1 损失及评估协议。只把大全连接头改为约 1,063 万参数的卷积头。先跑 30 轮，与旧模型第 10/20/30 轮同点比较；有希望再完成计划轮数。
2. **骨干对照：** [ConvNeXt Tiny 卷积头 recipe](../../configs/yolov1/voc2007_convnext_tiny_convhead.yaml)保持同一检测头形式和训练设置，将 backbone 及配套 TorchVision ImageNet 权重换成 ConvNeXt Tiny。预训练权重已按 recipe 的明确设置下载到本机 Torch 缓存。由于两个骨干的预训练模型本身不同，结果应解释为“骨干加其权重”的组合效果，不能单独归因于网络拓扑。先做同样的 30 轮比较。
3. **优化器/学习率对照：**若上述实验在第 60～80 轮也出现验证波动，再只改降学习率时点（例如从 75/105 提前到 60/90），保持模型和数据不变；或再独立比较 AdamW/SGD。没有受控结果前，不声称某个优化器更好。

所有训练继续使用 VOC2007 train/val，类别映射、448 直接缩放、困难目标省略、网格目标和 AP 定义保持一致。既往已经查看 VOC2007 test 的样例并据此制定改进，因此后续 test 分数应称为**训练外测试对比**，不再称为完全未接触的最终盲测；模型选择只根据 val。

## 首个受控对照：ResNet50 检测头

新增卷积头模型已用 ResNet18 官方缓存权重、ResNet50 本地官方权重验证 `[2,7,7,30]` 输出及有限的训练梯度；六个主干的最后特征在 448 输入下均已核对为 14×14。ResNet50 卷积头的 30 轮训练与验证已完成。两组同用 Adam、检测头 LR `1e-4`、骨干 LR `1e-5`，同一 train/val 划分、种子和评估协议；这里更换的是**整个检测头结构**，不只是参数数量。

| Epoch | 旧全连接头 mAP50 / mAP50:95 | 新卷积头 mAP50 / mAP50:95 |
| ---: | ---: | ---: |
| 10 | 0.0412 / 0.0140 | 0.2003 / 0.0495 |
| 20 | 0.0918 / 0.0306 | 0.3444 / 0.0938 |
| 30 | 0.1689 / 0.0606 | 0.3783 / 0.1066 |

参见[新 run 的训练曲线](../../runs/yolov1/voc2007-resnet50-convhead-20261001/training_curves.png)和[前 30 轮对照图](../../runs/yolov1/voc2007-resnet50-convhead-20261001/comparison_epoch30.png)。新头早期效果明显更好，因此旧模型早期表现差不能只归因于 Adam 或学习率；但新头第 20～30 轮 AP 增幅变小，尚不能推断完整训练上限。下一步先完成 ConvNeXt Tiny 的相同 30 轮对照，再从有希望的模型出发检验学习率调度。

逐类看，第 30 轮新头在 20 类中有 19 类 AP50 高于旧头、18 类 AP50:95 高于旧头；瓶子、盆栽等小目标依然弱。这是较广泛的改善，不是只靠一两个容易类别抬高均值。

[第 30 轮验证集可视化](../../runs/yolov1/voc2007-resnet50-convhead-20261001/predictions_val_conf025/contact_sheet.jpg)在置信度 `0.25` 下仍有明显漏检：桌椅图的椅子完全未检出，多牛图只检出一头，盆栽图把沙发识别出来但漏掉盆栽。这是实际输出限制，不能只用均值 AP 宣称结果已可用。

原论文使用动量 `0.9`、权重衰减 `0.0005` 和第 75/105 轮降学习率，且训练集为 VOC2007+2012；这里是 ImageNet 预训练骨干、Adam、VOC2007 train，数值不可直接照搬。[原论文训练说明](https://arxiv.org/html/1506.02640)。

## 非 ResNet 骨干初步对照

ConvNeXt Tiny 使用 TorchVision `IMAGENET1K_V1` 预训练权重及相同结构的卷积头。第 10 轮验证 mAP50 / mAP50:95 为 `0.2921 / 0.0753`，高于 ResNet50 卷积头同轮次的 `0.2003 / 0.0495`；第 20 轮分别为 `0.4205 / 0.1264` 对 `0.3444 / 0.0938`，20 类中有 18 类 AP50 提升；第 30 轮为 `0.4720 / 0.1538`，高于 ResNet50 的 `0.3783 / 0.1066`。参见训练曲线（历史 run 产物已清理）、骨干对照图（历史 run 产物已清理）和验证集预测图（历史 run 产物已清理）。推理图中的多头牛检测有改善，椅子、盆栽和小目标仍有漏检，不能据此宣称已达到实用上限。

首次训练进程在第 25 轮后收到外部 SIGTERM、无 Python 异常；原指标及日志保存为 `interrupted_*_epoch25`，第 20 轮 checkpoint 起恢复，并重跑第 21～25 轮。主 `metrics.jsonl` 使用恢复后的连续记录。

在 RTX 4060 Ti 上用同一个 ConvNeXt 模型、448 随机图和前后向短基准，FP32 物理 batch 4 为约 `32.5` 图/秒、batch 16 为约 `34.4` 图/秒，增益很小；batch 4 的 BF16 为约 `76.0` 图/秒。此为模型计算微基准，**不是**包含数据增强/验证的实际训练吞吐。BF16 一步真实数据续训及完整验证无数值异常，随后第 31～40 轮用 `--precision bf16`、相同物理/有效 batch、Adam 和学习率继续。阶段一 FP32 配方与运行环境已另存 `stage1_*`。

第 40 轮实际结果为 mAP50 / mAP50:95 `0.4855 / 0.1582`，只比第 30 轮多 `0.0135 / 0.0044`，而训练损失从 `1.879` 降到 `1.496`。此拐点提示学习率或泛化可能限制收益，不能单凭曲线判定哪一个。第 40 轮完整 checkpoint 已单独保留。随后以相同 checkpoint、BF16、Adam、数据顺序与有效 batch 分叉：[提前降 LR 配方](../../configs/yolov1/voc2007_convnext_tiny_convhead_early_decay.yaml)为 `50/90`，[原配方](../../configs/yolov1/voc2007_convnext_tiny_convhead.yaml)为 `75/105`。到第 70 轮比较验证集；前 40 轮为完全共享的训练前缀。

提前分支已到第 70 轮：[训练曲线](../../runs/yolov1/voc2007-convnext-tiny-early-decay-20261001/training_curves.png)。第 50 / 60 / 70 轮验证 mAP50:95 为 `0.1614 / 0.1766 / 0.1824`，mAP50 为 `0.4854 / 0.5119 / 0.5190`。原调度分支相同轮次为 `0.1612 / 0.1873 / 0.1947` 和 `0.4870 / 0.5313 / 0.5415`。因此在相同 checkpoint 和有效 batch 下，50 轮提前降 LR 到第 70 轮的验证 AP 较低，当前保留原 75/105 调度继续完整训练。第 51 轮训练坐标损失在两分支都从约 `0.29` 升至约 `0.65`，包括仍用 1e-4 的原分支，因此不能把跳升归因于降 LR；训练增强损失也不能直接替代验证定位指标。两分支第 41～49 轮训练损失逐位一致，确认分叉前条件重合。

第 70 轮调度对照图（历史 run 产物已清理）显示，两组验证曲线在第 50 轮前重合；提前分支降 LR 后虽继续上升，原调度分支在 60、70 轮都更好。原调度分支之后完成 135 轮训练，详见下方完整结果。

## 更多骨干的受控筛选

为决定是否值得投入完整训练，保持相同 Conv2d/GroupNorm 检测头、VOC2007 train/val、种子、batch、增强、Adam 和学习率，对 RegNetY-800MF、ResNeXt50 32x4d 各做 30 轮筛选。两者分别使用 TorchVision `IMAGENET1K_V2` 权重和 BF16；每 10 轮验证和更新 `last.pt`；`best.pt` 单独指向本 run 验证集最佳轮次。结果都明显落后，因此停止在预定筛选轮数，不扩成 135 轮。新筛选与更早的 ResNet50/ConvNeXt 30 轮曲线在精度上不同（早期两者为 FP32，新筛选为 BF16），所以和历史曲线的横向数值是方向性筛选，不是严格单变量消融；BF16 只用于训练前向，验证及 loss 仍为 FP32。

| 骨干 | Epoch 10 mAP50 / 50:95 | Epoch 20 | Epoch 30 |
| --- | ---: | ---: | ---: |
| ResNet50 + conv head | 0.2003 / 0.0495 | 0.3444 / 0.0938 | 0.3783 / 0.1066 |
| ConvNeXt Tiny + conv head | 0.2921 / 0.0753 | 0.4205 / 0.1264 | **0.4720 / 0.1538** |
| RegNetY-800MF + conv head | 0.1309 / 0.0289 | 0.1894 / 0.0432 | 0.2576 / 0.0630 |
| ResNeXt50 32x4d + conv head | 0.1693 / 0.0369 | 0.2501 / 0.0595 | 0.2714 / 0.0669 |

四骨干对照图（历史 run 产物已清理）并列了第 30 轮的 loss、验证 AP 与学习率；逐轮数值和精度标注见对照 CSV（历史 run 产物已清理）；RegNet 的[训练曲线](../../runs/yolov1/voc2007-regnet-y-800mf-convhead-pilot-20261001/training_curves.png)和 ResNeXt 的[训练曲线](../../runs/yolov1/voc2007-resnext50-32x4d-convhead-pilot-20261001/training_curves.png)分别保存在 pilot run 中。两者到 30 轮仍低于 ResNet50，暂无证据支持为它们投入完整训练预算。不同 ImageNet 预训练权重与骨干一起改变，结论应视作完整预训练组合在当前配方下的工程筛选。

## 完整训练、学习率结论与 test 结果

ConvNeXt Tiny 卷积头按原调度完成 135 轮，每 10 轮更新 `last.pt`，另用 `best.pt` 保留验证指标最高的权重；第 100 轮验证集 mAP50:95 最高，为 `0.2076`，因此 `best.pt` 选中第 100 轮，而不是最后一轮。训练完成时第 135 轮验证 mAP50 / mAP50:95 为 `0.5607 / 0.2074`，和最佳点接近，没有后期崩溃迹象。全程训练损失继续下降，但验证集从约第 90 轮起基本进入平台。

### 学习率与优化器判断

受控实验从相同第 40 轮 checkpoint 分叉，只改变学习率衰减点：原方案 `75/105`，提前方案 `50/90`。第 50 / 60 / 70 轮提前方案 mAP50 为 `0.4854 / 0.5119 / 0.5190`，原方案为 `0.4870 / 0.5313 / 0.5415`；mAP50:95 分别为 `0.1614 / 0.1766 / 0.1824` 与 `0.1612 / 0.1873 / 0.1947`。提前衰减到 70 轮时两项都更差。原方案第 75 轮降学习率后，到 80 轮验证指标明显上升。因此当前证据支持保留第 75 轮首次衰减。

105 轮第二次衰减后 mAP50:95 小幅下降，后续回到平台；它没有带来清晰的持续增益，也没有导致模型崩溃。Adam 的训练损失平稳下降，没有发散证据；**还没有**同模型同数据的 AdamW 或 SGD 对照，不能把 Adam 判定为最优，也不能说优化器就是性能瓶颈。训练损失中坐标项在 51 轮附近上升，但提前与原方案都出现、且发生时原方案 LR 没变；这是训练增强/分项波动，不等于验证定位变差。

### 测试集结果与可视化

使用验证集选择出的第 100 轮 `best.pt` 对 VOC2007 test 的 4,952 张图完成评估：mAP50 `0.56684`、mAP50:95 `0.21128`，评估配置置信度下限 `0.001`、最多保留 100 个检测框。旧 ResNet50 大全连接头为 `0.51765 / 0.21241`：ConvNeXt 的 mAP50 提升 `0.04919`，mAP50:95 变化 `-0.00113`。逐类 AP50 有 16/20 类提升；AP50:95 有 12/20 类提升。这说明整体更容易把目标排到前面并检出，但高 IoU 定位没有整体提升。两个模型的检测头/骨干不同，且 ConvNeXt 后 105 轮使用 BF16、ResNet 旧 run 为 FP32；test 差异用于工程比较，不是只改变 backbone 的严格消融。

test 逐类差值见对比图（历史 run 产物已清理）与数值 CSV（历史 run 产物已清理）。训练曲线（历史 run 产物已清理）、test 各类 AP（历史 run 产物已清理）、数据集分析图（历史 run 产物已清理）和置信度 0.25 的 test 预测拼图（历史 run 产物已清理）已落盘。0.25 拼图较干净，但仍漏小物体、拥挤物体并有定位不准；0.10 拼图会多出明显误检。阈值只能改变展示取舍，不会修复模型定位。

### 数据与模型的限制

训练集有 2,501 张图、6,301 个框；`person` 有 2,358 个框，而 `diningtable` 仅 103 个。原始 YOLO 标注扫描显示，7×7 网格下训练集 289 张图有同格中心点冲突，共 421 个额外目标；test 对应 558 张图 / 823 个额外目标。当前 target 编码在单个样本的同一格多目标时保留面积最大的框、忽略其余框；数据增强会改变中心点落格，因此每轮具体冲突会变化，实际训练日志每轮约忽略 430–495 个目标。训练框面积中位数约占图像 `0.0998%`，第 10 百分位为 `0.0107%`；test 评估仍使用全部标注。这些统计与小目标漏检、密集目标表达受限、AP50:95 不升相符，但不单独证明其因果比例。

这轮实现仍保留 YOLOv1 的 7×7 单层网格和损失，换用 ImageNet 预训练骨干及空间共享卷积检测头，属于**教学/工程变体**而非原论文严格复现。VOC2007 test 过去已被可视检查过，因此这里记为训练外测试对比，不称作全盲最终测试。完整原始指标和检测图分别在 run 目录（历史 run 产物已清理） 与本报告上方的链接中。
